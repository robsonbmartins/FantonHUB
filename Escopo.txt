Além disso, ela poderia oferecer recursos que o MIDI-OX não tem, como:

suporte completo a VM_MASTER_IN e VM_MASTER_OUT.




1. Camada de Descoberta (Mapeamento USB para MIDI)
O script deve inicializar resolvendo o problema de identificação para não depender de nomes genéricos que o Windows possa embaralhar.

Tabela de Referência: O script deve conter um dicionário ou arquivo de configuração com os VIDs e PIDs dos hardwares alvos (os modelos Steinberg CMC-PD e CMC-FD).

Varredura de Hardware: Utilizando bibliotecas de sistema operacional (como pyusb no Python, ou consultas via WMI), o script varre os barramentos USB ativos e encontra em quais instâncias lógicas os controladores estão conectados.

Resolução de Nomes: O script correlaciona essas instâncias de hardware com as portas MIDI (MME) ativas no sistema para travar as referências corretas para as portas que o sistema nomeou como Steinberg CMC-PD-1, PD-2, PD-3 e 2 - Steinberg CMC-FD-1.

2. Camada de Roteamento de Entrada (Soma)
Observando as linhas de conexão da esquerda para a direita no image_c9d7a1.png, todos os controladores físicos enviam sinal para um único destino.

Abertura de Listeners: O script abre rotinas de escuta nas portas de entrada do hardware identificadas no passo anterior.

Regra de Encaminhamento: Qualquer evento MIDI (Note On/Off, CC) recebido nas portas CMC-PD-1, CMC-PD-2, CMC-PD-3 ou CMC-FD-1 deve ser somado e encaminhado imediatamente para uma única porta de saída: VM_MASTER_IN.

3. Camada de Roteamento de Saída (Distribuição/Broadcast)
Analisando as linhas que partem da entrada VM_MASTER_OUT no image_c9d7a1.png, ocorre um comportamento de "broadcast", vital para enviar o feedback visual (LEDs) de volta aos controladores.

Escuta Virtual: O script abre um Listener na porta de entrada virtual VM_MASTER_OUT.

Regra de Replicação: Quando uma mensagem MIDI chegar nesta porta, o script deve replicá-la e enviá-la simultaneamente para as portas de saída físicas de todos os controladores na mesa: CMC-PD-1, CMC-PD-2, CMC-PD-3 e CMC-FD-1.

4. Gestão de Estado e Execução
Processamento Assíncrono: Para manter a latência próxima de zero, essencial para MIDI, o loop de roteamento do script deve ser não-bloqueante (assíncrono), processando a fila de eventos de entrada e saída simultaneamente.

Resiliência de Conexão (Hotplug): Caso a rotina de hardware identifique que a conexão com um VID/PID específico foi perdida (cabo desconectado), o script deve fechar aquela porta logicamente sem travar o tráfego dos controladores restantes, reiniciando uma escuta periódica pelo VID/PID ausente para reconectá-lo automaticamente quando voltar.
